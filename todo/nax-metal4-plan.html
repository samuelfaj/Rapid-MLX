NAX / Metal4 Tensor API — Lightning-MLX implementation plan

PLANNING Created 2026-05-23 Inspired by antirez/ds4

antirez's ds4 ships custom Metal 4 Tensor kernels and reports 40–80% prefill speedup on M5 Max via Apple's Neural Accelerators (NAX). This plan lays out how Lightning-MLX captures the same wins, in tiers, without regressing M1–M4 users.

Custom kernels here

Hot path

3. How antirez/ds4 did it

Detection (ds4_metal.m)

g_metal4_family_supported = !metal4_disabled
    && [g_device supportsFamily:MTLGPUFamilyMetal4] ? 1 : 0;
g_metal4_queue_supported  = [g_device respondsToSelector:@selector(newMTL4CommandQueue)] ? 1 : 0;
if (g_metal4_family_supported && ds4_gpu_device_name_contains("M5")) {
    g_metal4_m5_neural_accelerators_hint = 1;
}

Plus a compile-time probe: tries to build a test tensor kernel; on failure logs "Metal 4 tensor API probe failed; using legacy Metal kernels" and falls back.

Kernels (metal/dense.metal 578 LOC, metal/moe.metal 753 LOC)

Everything guarded by #ifdef DS4_METAL_HAS_TENSOR. Includes:

#include <metal_tensor>
#include <MetalPerformancePrimitives/MetalPerformancePrimitives.h>

APIs used:

  • matmul2d + matmul2d_descriptor
  • tensor() with dextents<int32_t,2>
  • execution_simdgroups<4>
  • get_destination_cooperative_tensor
  • simdgroup_load / simdgroup_store / simdgroup_multiply_accumulate

Tile params: 64×32 output, NK=32 inner, NL0=2 / NL1=4 loader splits. Direct-RHS variants pin NR0=64, sweep NR1 ∈ {32, 64, 128}.

Strategy:

  • Dense GEMM: dequant weight → fp16 staging in threadgroup mem → cooperative matmul2d on 4 simdgroups → store.
  • MoE: pre-computed expert-major index map keeps cooperative matmul dense per tile.
  • Quant matvec (decode): stays legacy — memory-bound, tensor doesn't help.

Validation harness (later cleaned up)

Initial commit added ~11K LOC of drift & bench tooling. Cleanup commit removed most of it but the pattern is informative:

  • compare_logit_drift.py — logit-level diff vs legacy path
  • run_chunked_prefill_drift_gate.py — chunked prefill correctness
  • run_mpp_compare_probe.py — MPP A/B probe
  • run_quality_drift_gate.py — end-to-end quality drift

5. Metrics framework — before / after

Mandatory. Every tier captures a fresh BEFORE snapshot, applies changes, captures AFTER, writes a comparison row. No tier ships without paired data committed to reports/nax/.

5.1 Snapshot fields (per cell)

  • prefill_tok_s — median of N=3 runs
  • gen_tok_s — median of N=3 runs
  • first_token_ms — TTFT
  • peak_rss_mb
  • peak_gpu_mem_mb — via mx.metal.get_peak_memory()
  • mtp_accept_rate, ngram_accept_rate
  • env: mlx_version, lightning_mlx_sha, macos_version, device_name, nax_enabled

5.3 Bench command (anchor — same flags every run)

lightning-mlx bench <model> \
  --num-prompts 3 --max-tokens 512 --disable-prefix-cache \
  --max-num-seqs 1 --prefill-batch-size 1 --completion-batch-size 1 \
  --prefill-step-size 8192 --mtp-num-draft-tokens 3 --mtp-optimistic \
  --ctx-size <ctx> \
  --report-json reports/nax/<tier>/<run-id>.json

NAX-off variant: LIGHTNING_DISABLE_METAL4=1 env (introduced in T2.3). For T1 baseline use MLX_DISABLE_METAL4=1 if MLX exposes it, else rebuild MLX without 0.30+ support.

6. Tiered plan

T1 — Free win (audit + verify + measure)

Effort: hours • Risk: none

  1. prereq_bench_tooling — finish §5.6 M1–M7. Blocking.
  2. capture_baseline_t0 — run sweep on all 3 hw with current MLX 0.31.2 → reports/nax/t0_baseline/. Commit.
  3. verify_mlx_nax_path — on M5 Max + macOS ≥ 26.2, dump mx.metal.device_info(), confirm tensor kernels selected.
  4. bump_mlx_floor — raise pyproject.toml to mlx>=0.30.0. Re-lock.
  5. capture_after_t1 — re-run sweep on all 3 hw → reports/nax/t1/.
  6. bench_decode_breakout — extract decode rows + first-token-ms.
  7. bench_mtp_acceptance — verify acceptance Δpp ≤ 1.
  8. drift_gate_t1 — mean abs ≤ 1e-3 vs t0 baseline.
  9. gen_summary_t1 — scripts/nax_summarize.py t0_baseline t1 → summary.md. Commit.
  10. doc_update — README on M5 + macOS 26.2 requirement.

Files: pyproject.toml, uv.lock, README.md, new reports/nax-t1-bench.md.

Gate: if P1 + P2 met by upstream alone → ship, stop. If <50% of gain captured → T2 mandatory.

T2 — MTPLX custom kernel audit + Metal4 path

Effort: days • Risk: medium • Gate: only if T1 leaves >15% headroom

  1. audit_custom_kernels — exhaustive grep for mx.fast.metal_kernel, @mx.compile, raw Metal sources across vllm_mlx/{models,speculative,attention.py,optimizations.py}. Classify GEMM vs other.
  2. identify_matmul_hot_paths — profile MTP draft verify, n-gram verify batched matvec, custom prefill GEMM. Drop anything < 2% of total time.
  3. add_metal4_gate — new module vllm_mlx/runtime/metal4.py:
    • metal4_available() -> bool
    • m5_nax_hint() -> bool
    • Env override LIGHTNING_DISABLE_METAL4=1
  4. port_matmul_kernels — for each hot GEMM kernel, add Metal4 variant guarded by #ifdef LMLX_METAL_HAS_TENSOR. Start tiles at ds4's 64×32, NK=32, 4 simdgroups.
  5. drift_harness — port slim evals/nax_drift_gate.py from ds4. Fail on mean abs > 1e-3 or max abs > 1e-2 at 4k / 16k / 64k.
  6. ci_gate — blocking on M5 CI if available, else documented manual gate.
  7. capture_before_t2 — re-snapshot from reports/nax/t1/ as T2 baseline. Confirm hashes match committed JSON.
  8. bench_t2 — re-run sweep on all 3 hw after kernel ports → reports/nax/t2/.
  9. drift_gate_t2 — diff vs T1 baseline AND vs legacy-off path. Both required.
  10. gen_summary_t2 — scripts/nax_summarize.py t1 t2 → summary.md. Commit.

Gate: all of P1–P5.

T3 — Full custom Metal4 kernel suite (fork-and-tune)

Effort: weeks • Risk: high • Gate: only if T1+T2 still leave >15% headroom AND priority justifies maintenance

  • Hand-tuned Metal4 kernels replacing MLX matmul for hot shapes only: q/k/v/o proj fused, gate_up_proj fused for SwiGLU, MoE expert GEMM (mirror ds4's metal/moe.metal).
  • Ship as MLX patch loaded at import time (existing pattern in vllm_mlx/patches/).
  • Per-layer logit gates in drift harness (max abs ≤ 1e-2 per layer).
  • capture_before_t3 — snapshot from reports/nax/t2/.
  • bench_t3 — sweep on all 3 hw → reports/nax/t3/.
  • gen_summary_t3 — diff vs T2. Commit.
  • Pin M5-only maintenance commitment in docs.
Default: do NOT enter T3 unless data forces it. Every custom kernel is debt.

7. Risks

IDRiskMitigation
R1HW fragmentation — NAX is M5+ only.Runtime gating mandatory. Legacy path always present.
R2OS requirement — macOS ≥ 26.2.Detect at startup. Graceful fallback. Doc it.
R3MLX version churn around NAX hooks.Pin minor (mlx + mlx-lm together). Snapshot lockfile.
R4MTPLX dispatch order interaction.T2.5 drift gate. T2.7 MTP acceptance bench.
R5Quant path — most models are 4/6/8-bit.Bench must confirm gain with dequant→fp16 staging (ds4 pattern).
R6Custom kernel maintenance debt.T3 only if measured ROI > 1 quarter eng time.

8. Hard no-go

  • N1 — no compile-time-only gating. Runtime detect mandatory.
  • N2 — no M5-only ship. Legacy fallback always present.
  • N3 — no kernel merge without drift gate green.
  • N4 — no MTP acceptance regression > 1pp.
  • N5 — do not touch existing HC kernels (deepseek_v4.py:420,606). Not GEMM, out of scope.
